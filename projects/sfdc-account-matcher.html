SFDC Account Matcher

Company lists kept arriving with no reliable way to check them against Salesforce. I built a matching tool that returned ranked candidates with a confidence score instead of a flat yes or no — so a reviewer got a reason to trust a match, not just a match.

The problem

Partner lists, event lists, campaign lists — they arrived constantly, and every one of them raised the same question: which of these are already accounts in Salesforce? A plain text match answered it badly. Name variants, abbreviations, and legal suffixes broke it on the easy cases, and parent/subsidiary structure broke it on the hard ones. A row for BNSF Railway needs to resolve to the Berkshire Hathaway account, and no amount of string comparison will ever get there.

Underneath that was a constraint I couldn't design around: no Salesforce API access. Not during the Clay trial, not on the base tier, not at any point. Whatever I built could not be a live lookup.

Two engines, and a third mode

  • Fuzzy string matching (rapidfuzz) for close textual variants — abbreviations, legal suffixes, formatting differences. This is what handles NTT DATA against NTT Data Corporation.
  • Semantic matching via a local sentence embedding model (all-MiniLM-L6-v2, running on torch) for names that are related without being textually similar. Embeddings for the whole account export are computed once and cached, then everything is scored against that matrix at once. This is the half that catches parent and subsidiary pairs.
  • Hybrid, which is the one worth using. Semantic runs first, and the names it didn't match fall through to fuzzy — the expensive engine goes first and the cheap one sweeps up behind it, rather than running both across everything and reconciling afterward.

Confidence, not verdicts

Every input came back with its top three candidates rather than one answer. Each candidate carried a name-similarity score and a domain-match score, blended into a single combined figure, then banded for triage:

BandScoreWhat happens to it
High90%+Trusted directly
Medium75–89%Worth a spot check
ReviewBelow 75%Flagged for a human

The banding is the whole design. A binary matcher fails silently in two directions — it creates duplicate accounts when it's wrong, and it drops real matches when it's cautious. Ranked candidates with a visible score turn both failure modes into a short queue somebody can work through in a few minutes.

Contacts work differently

The account side scores names against names. The contact side can't, because contacts have an actual identifier — so instead of one scorer it runs a priority cascade. An exact email match comes first and the name is then used to validate it rather than to decide it; a matching email whose name disagrees is a flag worth catching, not a match to trust. Only when email fails does it fall back to fuzzy name matching above a threshold the user sets.

The fallback doesn't score against every contact in the export, either. An inverted index of name words narrows the field to a small candidate set first, and fuzzy matching runs only on that — which is what keeps it usable against a full contact export rather than a sample.

Every result carries the method that produced it — Email + Full Name (98%), Name Only — Flexible (87%) — so a reviewer can see why something matched and not just how well. Same principle as the banding: give a person a reason, not a verdict.

Why it was an app

Packaged as a local Streamlit app rather than a notebook or a one-off script, so teammates without a Python environment could upload a CSV and get scored output back without touching code. That's what made it a standing step in how incoming lists got handled, rather than a cleanup someone ran once and forgot about.

The constraint that shaped it

No API meant batch, running against periodically exported account data. That's a consequence of the access limitation, not a preference — and worth stating plainly, because the same tool with API access is a different and simpler piece of software. The interesting work here was getting good answers out of a stale export, which is the situation most people are actually in.
